# Складно

Первый рабочий прототип обучающего веб-приложения по макету «Складно»: React + Vite, Node.js/Express, Prisma и PostgreSQL.

## Запуск на macOS

Проект работает в **cloud-only** режиме:

- PostgreSQL — REG.RU;
- пользовательские картинки, аудио и другие загрузки — REG.RU S3;
- локальная PostgreSQL и `public/uploads` приложению не нужны.

Обычный запуск:

```bash
cd ~/Desktop/english && git pull && npm run db:generate && npm run db:push && npm run dev
```

`scripts/setup-mac.sh` также работает только с уже настроенным облачным `DATABASE_URL` и намеренно не создаёт локальную базу.

## API

- `GET /api/health`
- `GET /api/dashboard`
- `PATCH /api/lessons/:id/progress`


## Аудиословарь

В админке есть общий аудиословарь: английская фраза хранится один раз, а уроки ссылаются на неё через поле `audioPhrase`. Для каждого из шести голосов можно загрузить свой файл. При открытии урока API автоматически подставляет актуальную запись из словаря; старые `audioFiles` в существующих уроках остаются резервным вариантом.

После обновления проекта с этой функцией нужно применить новую Prisma schema:

```bash
npm run db:generate
npm run db:push
```

При запуске через `scripts/setup-mac.sh` эти команды выполняются автоматически.


## Медиатека изображений

В админке есть общая медиатека. Каждой картинке задаётся название, после чего она загружается один раз и может использоваться в любом количестве заданий.

В редакторе задания кнопка «Выбрать картинку» открывает поиск по медиатеке. Поиск фильтрует варианты по части названия: например, запрос `Hello` покажет `Hello`, `Hello there`, `Hello everyone`. Задание хранит `mediaId`, поэтому замена файла у записи в медиатеке автоматически обновляет картинку во всех связанных заданиях. Старое поле `imageUrl` остаётся fallback для уже созданных уроков.

После обновления с медиатекой нужно применить Prisma schema:

```bash
npm run db:generate
npm run db:push
```

## Низкая задержка интерфейсных звуков

Короткие звуки интерфейса (click/success/error/end) предварительно загружаются и декодируются через Web Audio API с `latencyHint: "interactive"`. Обычный `HTMLAudio` остаётся резервным способом воспроизведения, если Web Audio недоступен.


## REG.RU: PostgreSQL + S3

Проект поддерживает перенос с локального PostgreSQL на облачный PostgreSQL REG.RU и загрузку пользовательских медиа в REG.RU Object Storage.

### База данных REG.RU

Текущая конфигурация проекта рассчитана на:

- PostgreSQL 17;
- host: `79.174.89.45`;
- port: `19538`;
- database: `db1`;
- user: `user1`;
- SSL: `sslmode=require`.

Пароль базы данных не хранится в Git и не сохраняется через админку. Он находится только в локальном `.env` в составе `DATABASE_URL`.

Для полного переноса текущей локальной базы выполни:

```bash
cd ~/Desktop/english
git pull
npm install
npm run db:migrate:reg
```

Скрипт:

1. применяет актуальную Prisma schema к текущей локальной базе;
2. создаёт резервную копию локальной PostgreSQL;
3. скрыто запрашивает пароль пользователя `user1` REG.RU;
4. проверяет подключение к облачной базе;
5. переносит все таблицы, связи и данные;
6. сохраняет старый `.env` рядом как backup;
7. меняет `DATABASE_URL` на REG.RU;
8. создаёт `STORAGE_MASTER_KEY`, если его ещё нет.

Резервные копии создаются в каталоге `backups/` и не попадают в Git.

### S3 REG.RU

В админке открой **Настройки → Хранилище REG.RU S3**.

Предзаполнены:

- endpoint: `https://s3.regru.cloud`;
- bucket: `angliskii`.

Project ID, Access Key ID и **Secret Access Key** вводятся в админке. Credential-данные намеренно не зашиваются в исходный код и не коммитятся в Git. Он никогда не возвращается обратно в браузер после сохранения.

Secret Access Key хранится в таблице `StorageSettings` в PostgreSQL в зашифрованном AES-256-GCM виде. Ключ расшифровки `STORAGE_MASTER_KEY` находится только в локальном/серверном `.env`, поэтому дамп базы сам по себе не содержит пригодного к использованию S3-секрета.

Кнопка **Проверить подключение** выполняет реальную проверку:

- доступ к bucket;
- тестовую запись объекта;
- публичное чтение этого объекта;
- удаление тестового объекта.

Новые картинки и аудио после настройки S3 загружаются напрямую в REG.RU. Эндпоинт также поддерживает общий тип `file` для будущих документов и других файлов.

### Cloud-only storage

Локальный путь `/uploads` отключён на уровне Express: сервер его не создаёт и не раздаёт. Все новые пользовательские загрузки идут только в S3.

В **Админка → Настройки** есть кнопка **Проверить отсутствие локальных ссылок**. Она сканирует облачную PostgreSQL и подтверждает, что ни голос, ни аудиословарь, ни медиатека, ни уроки не ссылаются на `/uploads/`.

После успешного переноса и проверки локальные артефакты можно удалить одной командой:

```bash
npm run cleanup:local-cloud
```

Команда имеет защиту: она выполняется только когда текущий `DATABASE_URL` указывает на REG.RU `79.174.89.45:19538/db1` и в облачной базе нет ссылок на `/uploads/`. После этого она удаляет старую локальную PostgreSQL `skladno`, каталог `public/uploads`, локальные dump-бэкапы миграции и старые `.env.local-backup-*`.
